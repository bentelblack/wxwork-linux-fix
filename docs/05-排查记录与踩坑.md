# 05 排查记录与踩坑

## 内嵌网页修复方案验证（2026-11-09）

1. **以官方环境为基座**：保留完整官方容器、运行库、注册表及启动配置，在其中安装 5.0.13.6005，避免同时改变容器和引擎等多个变量。
2. **只更改一个变量**：官方容器升级后群公告异常；保留官方 `files/dlls/`、`WINEPREDLL` 和启动助手，仅在独立引擎中额外覆盖 i386 `kernelbase` 后，群公告恢复。逐文件哈希确认差异，完全退出并重启，再检查进程实际映射和功能结果。
3. **不把账号数据带入构建**：实验使用独立测试环境，发布模板应从未登录的官方材料重新生成。

本轮已完成隔离环境的群公告验证。脚本已按官方基座和单模块覆盖修订，但字体视觉效果、新入口和最终 deb、在线更新仍待实测。目标方案见 [02](02-解决方案.md)，实施门禁见 [03](03-构建流程.md#target-build)。

## 排查方法

- **分段替换模块**：在 `~/work` 里复制几份 wine，每份只换一组模块，用同一个测试容器分别启动。每轮都用 `/proc/<pid>/maps` 确认进程实际加载的是哪个文件，不能只看文件放在哪里。
- **每轮记下启动时间**：主日志的文件名就是会话启动时间，用它把每轮测试和日志对应起来。
- **以日志为准**：界面上看到的"能下载""下载失败"不可靠，每轮都要解密日志核对。
- **改动前先备份**，测试只在副本和测试容器里做。

## 踩坑

以下包含历史旧实现的处理方式；涉及整套覆盖和双入口的条目不表示修订方案已经实现或重测。

| 问题 | 现象 | 原因 | 解决 |
|---|---|---|---|
| 新版 7-Zip 拒绝官方盘符链接 | 官方助手提示解压失败并删除临时容器 | `dosdevices/c: -> ../drive_c` 被危险链接检查拒绝 | 排除该条目，在固定容器位置显式重建；不要关闭危险链接检查 |
| 官方 banner 识别到现用实例 | 换前缀后仍直接退出 | 同一 X11 显示上的窗口类相同，文件和进程隔离不等于显示隔离 | 先从托盘退出现用程序，必要时使用独立显示服务器 |
| 官方 quit.sh 误杀测试包装器 | 窗口刚出现，隔离空间便退出 | 包装器命令行嵌入了完整官方入口路径，被路径匹配误杀 | 避免包装器命令行包含连续的匹配路径，独立管理隔离空间生命周期，不改官方退出脚本 |
| 仅凭当前日志外推旧根因 | 群公告异常就认定出现了 1400 | 本轮日志并未复现该条历史错误 | 保留历史证据边界，以当前日志与单变量功能对照核实 |
| 把测试结果记反 | 一度以为是 `user32` 的问题 | 只凭界面反馈和记忆对应轮次 | 解密日志，按会话启动时间对应轮次，结论全部重新核对 |
| 只看文件时间推断 | 以为 `sys_msvcrt` 是原因 | 用 `.Update.tmp` 的修改时间推断是哪一轮写的，推错了 | 以日志里的 `open fail` / `start download update file` 为准 |
| 关掉更新窗口 | 日志显示下载 1 秒多就中止 | 更新窗口关闭会取消下载 | 下载时不要关窗口 |
| 在日常模式里检查更新 | 用了双入口包仍然"下载失败" | 企业微信还在托盘里，用的是日常那套 wine | 先从托盘退出，再用右键"检查更新"。`run.sh` 检测到另一套 wine 在运行时会拦下并提示 |
| 按进程覆盖 `kernelbase` | `AppDefaults\WXWork.exe\DllOverrides` 和同目录 DLL 都被忽略，主进程闪退 | `kernelbase` 由 `ntdll` 在读取覆盖设置之前加载 | 放弃，改用双入口 |
| wineserver 版本对不上 | `Your wineserver binary was not upgraded correctly` | 定制模块里带了 `wineserver`，只覆盖 `lib/wine` 没换 `bin/wineserver` | `dlls/wineserver` 也要放到 `bin/` |
| 7z 改写符号链接 | 解压后 `com1 -> <解压目录>/dev/ttyS0` | 7-Zip 25 把绝对路径链接当成"危险链接"，改写到解压目录里 | 容器包改用 `tar.xz` |
| dpkg 建硬链接失败 | `新建硬链接 ./opt/.../wine-update/bin/msidb 时出错`，包停在半安装状态 | deb 里用硬链接做 `wine-update`，dpkg 解包时链接目标还没解出来 | 包里只放原版文件，`postinst` 里用 `cp -al` 生成 |
| 原包的升级逻辑会删容器 | 包版本号一变，首次启动就 `rm -rf` 整个容器 | deepin `pre_update.sh` 的设计就是删掉重建 | 自写 `run.sh`，升级只替换程序目录，并且用独立的容器目录 |
| 字体替换规则存在但字体不对 | 容器已有微米黑替换规则，实际回退到 Noto | 测试容器缺少字体文件，宿主也未提供微米黑 | 补齐 `wqy-microhei.ttc` 并登记，保留官方规则，重启后确认视觉效果 |
| 漏删家目录链接 | 模板里残留 `Templates -> /home/<构建者>/Templates` | 只删了 `users/<用户>/` 下的第一层链接 | `build.sh` 第 5 步在整个用户目录里递归查找指向家目录的链接 |
| `pgrep -f` 匹配到自己 | 进度循环一直不退出；误报"仍在运行" | 执行检查的 bash 命令行里本身就带着要查的字符串 | 按 PID 判断进程是否结束，或者用 `pgrep -f '[W]eCom'` 这种写法 |
| 加密日志 grep 不到 | 解密后按行过滤一行都没有 | 记录之间不是按换行分隔的；还有一种整文件异或的格式 | 按时间戳切分，两种格式都试 |
| wine 网络连接看不出是哪个进程 | `ss -tnp` 里的连接都记在 `wineserver` 名下 | wine 的 socket 由 wineserver 持有 | 对比点击前后新出现的目标地址，或者看日志里的 `curl_connection` |
