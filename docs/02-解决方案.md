# 02 解决方案

## 目标和已验证的组合

目标是修复 deepin-Wine 版企业微信的群公告等内嵌网页异常，同时保留官方运行环境，不把多个变量混在一次实验中。

2026-11-09 的 Debian 13 + GNOME / Wayland 隔离对照：

| 组合 | 群公告 | 在线更新 |
|---|---|---|
| 官方 5.0.10 容器安装 5.0.13.6005，沿用官方启动环境 | 异常 | 未测 |
| 同一配置，仅在配套 Wine 引擎目录额外换入官方定制 i386 `kernelbase.dll` | 正常 | 未测 |

通过文件哈希和 `/proc/<pid>/maps` 核对了实际加载来源。引擎相对原版只有 i386 `kernelbase.dll` 一处内容差异；官方 `files/dlls/`、`WINEPREDLL`、注册表、容器、运行库和图形探测环境全部保留。当前日志没有历史的 `CreateWindowEx Error = 1400`，不宣称已确认该错误是这轮现象的直接机制。

## 构建基座

- deepin Wine：`deepin-wine10-stable 10.14deepin14`。
- 官方企微容器与定制模块：`com.qq.weixin.work.deepin 5.0.10.6015deepin3`。
- 目标程序：腾讯官方 `WeCom_5.0.13.6005.exe`（实际文件名决定 deb 版本标签）。
- 图形探测及辅助组件：官方企微包的 `pre_run.sh`、`win32-test.exe`、`win32_voip_test.exe`，以及 `deepin-wine-helper 5.4.10-1` 的 GL 文件。
- 字体：Debian 官方 `fonts-wqy-microhei`。

构建从官方 `files.7z` 提取前缀，在未登录独立前缀里安装 EXE；不会用 `wineboot` 空前缀取代官方容器，也不复制现用账号数据。

## 引擎路径和兼容链接

Wine 加载器、服务端以及官方 `files/dlls/` 中部分二进制把 `/opt/deepin-wine10-stable` 编译进路径。把引擎搬到另一个根目录、再等长改写二进制，曾使 wine 启动时找不到 `l_intl.nls`，并扩大了需改写的二进制范围。

当前包把完整引擎作为普通目录打在：

```text
/opt/apps/com.qq.weixin.work.deepin/files/wine/
```

安装时 `postinst` 在 `/opt/deepin-wine10-stable` 创建指向该目录的兼容符号链接。若该路径已有其他目标，安装脚本拒绝覆盖。卸载时只删除目标确实指向本包引擎的链接。

引擎布局：

```text
files/
  wine/                  原版 Wine 引擎；仅 i386 kernelbase 是定制版
  wine-orig/             保存原版 i386 kernelbase
  wine-update/           postinst 生成的更新兼容引擎；只把该 kernelbase 恢复原版
  dlls/                  官方完整预加载模块（运行时仍通过 WINEPREDLL 使用）
  pre_run.sh             官方图形探测逻辑，GL 工具路径改为包内
  gl-wine/               官方 GL 探测及 GDI 回退组件
  fonts/                 微米黑字体
  font.reg               字体登记
  prefix.tar.xz          未登录的官方容器模板
  prefix.schema          official-v1
  prefix.version         程序版本标签
  run.sh                 日常/更新/本地安装入口
  wxwork-window-stack.py  将企微按钮辅助窗交给 Mutter 管理
```

更新引擎由 `postinst` 用 `cp -al` 从日常引擎创建，再先删除目标 hardlink、复制原版 kernelbase。不得原地覆盖共享 inode，否则会连带改变日常引擎。deb 本身不打两套 hardlink 引擎。

## 日常与更新入口

| 入口 | 引擎 | 适用范围 |
|---|---|---|
| 普通图标 | 定制 i386 `kernelbase` 的日常引擎 | 日常使用，群公告隔离验证通过 |
| 右键“更新兼容模式”或 `run.sh --update` | 原版 i386 `kernelbase` 的更新引擎 | 历史兼容设计；新组合的在线更新仍待实测 |
| `run.sh --install /path/WeCom.exe` | 更新引擎，安装到当前兼容前缀 | 与客户端内在线下载器是不同路径；不可据此推断在线更新已验证 |

历史测试中定制 kernelbase 使在线更新在本地临时文件创建时报 `open fail (22): Invalid argument`。新组合继续使用该模块，所以日常模式存在同类风险的判断来自历史记录，不是本轮在线更新结果。

两种引擎共用同一前缀，不能并行运行。关闭主窗口不等于退出托盘；切换入口、升级或安装前必须从托盘完全退出。运行器用前缀锁和同前缀进程检查避免并行改动。

## 企微按钮条与窗口层级

企微会在主窗顶部另建一个 1080×28 X11 对话窗口，`WM_TRANSIENT_FOR` 指向主窗，但该窗口带有 `Override Redirect`，绕过 Mutter 的普通窗口堆叠管理。现场验证表明，主窗被其他应用盖住后，这条按钮窗仍可见并截获点击；只取消映射它，按钮消失且点击穿透到下方应用。

只有 `.fixed-webview-level.deb` 包含层级辅助程序；`.fixed-webview.deb` 不包含、不启动该程序。两个变体沿用同一官方包名和版本，切换时先完全退出企微，再用 `apt install --reinstall ./所选文件.deb` 覆盖安装，共享原前缀。具体文件名、安装命令和验证环境见 [README](../README.md)。

level 版运行器随 WXWork 会话启动事件驱动的 X11 辅助程序，只处理同时满足 WXWork `WM_CLASS`、主窗 transient 关系、同宽且 24–40px 高、override-redirect 的窗口。程序将其解除映射、清除 override-redirect、保留 transient 关系及无装饰提示后重新映射，使 Mutter 将其纳入正常堆叠；窗口创建、映射、属性和几何事件触发检查，不做定时轮询、不读取活动窗口。企微退出时辅助程序一并结束。

在 Debian 13 GNOME 48.7 上，对实际按钮窗进行可逆试验后，Mutter 窗口列表包含该窗口，override-redirect 变为 no，按钮仍可用，切到 Claude 后随主窗退到下层。运行时仅转换符合上述窄条件的企微按钮条；遇到缺少 X 显示或身份条件不匹配时不做操作。Wine 若重建按钮窗，事件监听会再次按相同规则转换。

该处理依赖 XWayland 与 Mutter 接管 override-redirect transient 的行为；GNOME/Mutter 或企微版本变化后需重新验证按钮、拖动、最小化、关闭与堆叠。它不处理原生 Wayland 窗口，也不强制改变系统其他应用的层级。

## 字体

官方替换规则映射到 `WenQuanYi Micro Hei`，构建时补齐 `wqy-microhei.ttc` 并导入字体登记，不改 DPI、窗口尺寸或全局映射。文件和登记可自动验证；字体实际观感须重启后检查。

## 前缀及数据保护

- 默认前缀：`~/.deepinwine/WXWork-official-bundled`；可用 `WXWORK_PREFIX` 指定兼容布局的独立路径。
- 不自动迁移或删除旧的 `Deepin-WXWork`、`WXWork-bundled` 等前缀。
- 首次部署先校验 tar 条目与链接，再在同目录临时前缀解包，完整后再切换。
- 前缀存在但布局不兼容时拒绝覆盖；软件升级更换程序目录并保留旧程序备份，不清除账号数据。
- 卸载 deb 不自动删除用户前缀；需自行备份后单独清理。
