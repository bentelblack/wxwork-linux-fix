# 03 构建流程

<a id="build-preparation"></a>

## 构建前准备

- Debian 系 amd64，普通用户及已登录的图形桌面会话，Wine 可访问 XWayland `DISPLAY`。
- 建议预留至少 15 GB，保留安装材料、独立容器、模板、deb 及旧产物备份。
- 工具：Bash、GNU coreutils/find/grep/sed/awk、`dpkg-deb`、`fakeroot`、`tar`、`xz`、`7z`、`python3`、`apt-get`、`sha256sum`；下载材料用 `curl`。
- Wine 和 GL 组件的运行库必须可用；缺失时按错误补齐，不用安装旧企微来隐式配置系统。
- 构建不改系统 Wine、不安装软件、不登录账号，也不复制现用账号数据。

材料：

| 材料 | 用途 |
|---|---|
| `WeCom_5.0.12.6026_200003.exe` | 腾讯官方目标程序（当前更新测试版本） |
| `deepin-wine10-stable_10.14deepin14_amd64.deb` | 原版引擎 |
| `com.qq.weixin.work.deepin_5.0.10.6015deepin3_amd64.deb` | 官方容器、定制模块、图形探测及图标 |
| `deepin-wine-helper_5.4.10-1_amd64.deb` | 必要 GL 辅助文件及许可 |
| Debian `fonts-wqy-microhei_0.2.0-beta-4_all.deb` | 可放入 `.ready/`；缺失时从 Debian 官方源下载并校验 SHA-256 |

### 官方材料来源

EXE 从[腾讯企业微信官网](https://work.weixin.qq.com/)获取。deepin 材料通过官方应用商店索引查找 `Filename`、`Version`、`SHA256`：

```text
https://com-store-packages.uniontech.com/appstore/dists/eagle/appstore/binary-amd64/Packages.gz
```

下载地址为 `https://com-store-packages.uniontech.com/appstore/<Filename>`，脚本直连下载并跟随 307 跳转，同时携带浏览器 User-Agent 和官方商店 Referer。以索引实际版本和校验值为准，不猜测新版本地址。

deepin 材料缺失时，脚本按预设包名和目标版本从官方索引定位下载地址并保存到 `.ready/`；已有缓存或用户指定文件不做版本比对。默认材料应保持与记录的官方方案配套；更换材料后兼容性需另行验证，不跨版本拼接 DLL。

字体包固定从 Debian 官方 `deb.debian.org` 的 `fonts-wqy-microhei_0.2.0-beta-4_all.deb` 获取，脚本校验 SHA-256 后保存到 `.ready/`；也可自行提前下载放到该目录。该字体包版本与哈希固定在构建脚本中，若 Debian 更新字体包，需先审查并更新脚本中的下载地址和校验值。

## 构建命令

```bash
scripts/build.sh
```

不传参数时，脚本下载 EXE 和缺失材料；也可只传企业微信 EXE，或在 EXE 后按顺序提供 Wine deb、官方企微 deb、Helper deb、字体 deb。文件名包含四段版本号时仅用于构建标签，不检查 EXE 或其他输入文件版本；没有时使用 `unknown-version`，deb 元数据写为有效版本 `0.0.0.0+unknown`。从仓库根目录传入文件名时，脚本也会在 `.ready/` 中查找同名文件。

```bash
scripts/build.sh WeCom_5.0.12.6026_200003.exe
```

```bash
scripts/build.sh WeCom_5.0.12.6026_200003.exe deepin-wine10-stable_10.14deepin14_amd64.deb com.qq.weixin.work.deepin_5.0.10.6015deepin3_amd64.deb deepin-wine-helper_5.4.10-1_amd64.deb fonts-wqy-microhei_0.2.0-beta-4_all.deb
```

所有在线下载材料缓存到 `.ready/`，后续构建优先复用。默认 EXE 名称直接取当前配置下载 URL 的 basename。每次构建只准备一次公共 Wine/前缀模板，顺序生成 `.fixed-webview.deb`（不含层级辅助程序）与 `.fixed-webview-level.deb`（包含辅助程序）及各自的 `.sha256`。两包 Package 均为 `com.qq.weixin.work.deepin`，版本一致，`X-WXWork-Fix` 字段和 Description 区分变体；安装选择和已验证环境见 [README](../README.md)。

- 两包均构建、解包校验成功后才发布；构建/验证失败不移动既有产物。发布前将同版本、同变体的旧 deb 和校验文件移入 `build/backup/`，不会清空其他版本或旧命名产物。
- 构建中间文件只放 `build/.middle-file/`；成功后删除，失败时保留供排查。根目录 `.logs/` 始终保留，不清理。
- 构建输出目录固定为仓库 `build/`，避免误清理其他路径。
- 本轮脚本修订不表示已生成新 deb；未重新构建的 Release 不会自动变更。

## 构建步骤

1. 解出原版 Wine，核对版本及材料。
2. 解出官方应用容器和辅助文件，验证归档成员与链接；固定盘符排除后显式重建，不关闭链接安全检查。
3. 规范化用户名和引擎链接，在独立官方容器中用原版引擎及官方 `WINEPREDLL` 安装目标 EXE；检查安装退出码和主程序文件是否生成，不比对输入或安装后文件的版本。
4. 保留官方注册表；下载并加入微米黑字体，导入字体登记。字体规则沿用官方容器，不附加无条件 GDI。
5. 完全停止构建前缀内进程，制作未登录模板，清理临时内容但保留必要目录；替换构建者用户名、路径和引擎链接。
6. 日常引擎仅额外替换官方定制 i386 `kernelbase`，保存原版；把编译期引擎根等长重定位到包专用路径，保留 `files/dlls/`。
7. 打包公共运行文件。仅 level 变体额外包含 `wxwork-window-stack.py`；运行器检测文件存在才启动它，收到 X11 窗口事件后将匹配的企微 override-redirect 按钮条交给 Mutter 管理。无 helper 的网页版不启用层级修复。
8. 生成前缀模板并复用同一 staging 树，先构建网页版，再加入 helper 构建 level 版，分别核对包名、版本、变体字段、运行文件、helper 有无及 SHA-256。两包验证完成后备份对应旧产物并发布。

`prefix-tool.py` 处理官方归档与已知路径规范化。读取归档时用 `python3 -I`，不从下载或解包目录运行解释器。版本号只从 EXE 文件名提取，普通文件名不包含版本时使用 `unknown`。

## 安装后的实际验收

- 使用全新的 `WXWork-official-bundled` 或独立 `WXWORK_PREFIX`。旧布局不自动迁移、不删除旧目录。
- 主程序确为目标版本，官方 `DllOverrides` 和组件保留。
- 日常引擎与原版仅 32 位 `kernelbase` 一处不同；更新引擎恢复原版，实际进程映射与选择的模式相符。
- 群公告、邮件、在线文档逐项验证。
- 字体文件和注册表登记存在，重启后确认视觉效果；不擅自改 DPI。
- 在线更新与 `--install` 分开测试；未验证在线更新时保持“依据历史记录推测”的标记。
- 更新完成后退出托盘，切回日常入口重新检查网页。
- 验证同布局升级保留账号数据、旧程序目录备份及失败保护；旧布局兼容性不假定成立。

本轮不自动安装系统 deb，不主动触发在线升级。未完成的界面、网络或最终包测试必须保留在验证边界中。
